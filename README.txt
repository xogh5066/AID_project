AID Data Lab — 배포 및 다중 모델 검토 통합 안내
==================================================

1. 프로그램 소개
----------------
AID Data Lab은 CSV 데이터 분석·예측·통계적 추론을 실습하고,
학생이 작성한 해석을 여러 AI 모델과 사람이 검토하는 교육용 웹입니다.

기본 학습 흐름
CSV 또는 가상 데이터 준비 → 탐색·통계 → 회귀 학습·평가 → 새 값 예측
→ 평균 신뢰구간 계산 → 세 답안 작성 → 외부 전송 동의
→ 다중 AI 검토 → 사람 검토 기록 → 결과 저장

주의: 여러 AI가 CSV 예측값을 각각 계산해 평균내는 서비스가 아닙니다.
통계·회귀 계산은 브라우저에서 수행하며, AI는 제공된 계산 근거와
학생 답안의 해석 타당성을 검토합니다.


2. 현재 실행 경로와 파일 구성
-----------------------------
현재 배포판은 app.py → ensemble.py의 다중 모델 평가 경로를 사용합니다.

- app.py: Flask 웹 앱, 입장 코드, 세션, 요청 토큰 확인, 요청 제한
- index.html: CSV 분석·실습·AI 요청·사람 검토 화면
- ensemble.py: 모델 설정 검증, 모델별 요청, 응답 검증, 통합 판단
- core.py: 요청 검증(validate)과 기존 단일 모델 평가 코드
- models.example.json: 다중 모델 설정 형식 예시
- requirements.txt: 배포에 필요한 Python 패키지

core.py의 AI_API_URL / AI_API_KEY / AI_MODEL 및 config.json 관련 코드는
기존 단일 모델 평가용입니다. 현재 app.py의 다중 모델 피드백 경로에는
사용되지 않으므로, 아래의 ENSEMBLE_MODELS_JSON 방식으로 설정하세요.


3. 배포 준비
------------
HTTPS를 제공하는 Python 웹 호스팅에 필요한 파일을 함께 배치합니다.
호스팅에서 requirements.txt의 의존성을 설치하고 app:app을 실행합니다.

시작 명령 예시
  gunicorn --workers 1 --threads 4 --timeout 120 app:app

호스팅 서비스가 별도 포트 옵션을 요구하면 해당 서비스의 안내에 맞춰
추가 설정하세요. 위 구성은 단일 인스턴스 구현을 위한 예시입니다.

app.py를 가져오는 것만으로 서버가 시작되지는 않습니다.
HTML 파일을 직접 여는 방식에서는 AI 요청이 차단됩니다.
AI 사용 시에는 app.py가 index.html과 API를 제공하는 HTTPS 주소로 접속하세요.

기존 안내에 기재된 주소
  https://aid-project.onrender.com

현재 위 주소에서 웹 서비스를 확인할 수 있습니다.
입장하시기 위하여 입장코드가 따로 필요합니다.


4. 필수 환경변수
----------------
환경변수는 호스팅 서비스의 비밀값 설정 기능으로 등록하세요.
실제 API 키·입장 코드·세션 비밀값을 소스 코드나 공개 저장소에 넣지 마세요.

SESSION_SECRET
  추측 불가능한 긴 임의 문자열입니다. 32자 이상을 권장합니다.
  재시작 후에도 동일한 값을 유지하도록 배포 환경에 고정 등록하세요.
  현재 코드는 누락 시 임의 값을 생성하지만, 배포 시에는 명시적으로
  설정하는 것을 권장합니다.

ACCESS_CODE
  심사·수업용 공통 입장 코드입니다. 12자 이상이어야 합니다.
  사이트 주소와 별도로 필요한 대상에게만 전달하세요.

ENSEMBLE_MODELS_JSON
  서로 다른 모델 식별자 2~3개를 담은 JSON 배열입니다.
  models.example.json의 구조를 참고하되, 주소와 모델 식별자는
  실제 서비스에서 허용되는 값으로 교체하세요.

MODEL_A_KEY / MODEL_B_KEY / MODEL_C_KEY
  각 모델 호출에 사용할 실제 비밀 API 키입니다.
  MODEL_C_KEY는 세 번째 모델을 사용하는 경우에만 필요합니다.
  환경변수 이름은 JSON의 key_env와 정확히 일치해야 합니다.

설정 구조 예시 — 아래 값은 형식 설명용이며 그대로 사용할 수 없습니다.
[
  {
    "key_env": "MODEL_A_KEY",
    "model": "REPLACE_WITH_MODEL_A_ID",
    "url": "https://YOUR_AI_SERVICE/CHAT_COMPLETIONS_ENDPOINT",
    "weight": 1
  },
  {
    "key_env": "MODEL_B_KEY",
    "model": "REPLACE_WITH_MODEL_B_ID",
    "url": "https://YOUR_AI_SERVICE/CHAT_COMPLETIONS_ENDPOINT",
    "weight": 1
  }
]

각 항목의 의미
- key_env: 실제 API 키가 저장된 환경변수의 이름. 키 자체를 넣지 않습니다.
- model: 계정에서 사용할 수 있는 정확한 모델 식별자. 서로 달라야 합니다.
- url: Chat Completions 호환 API의 전체 HTTPS 주소
- weight: 유한한 양수 가중치. 기본값은 1

주소, 모델 이용 권한, 요청·응답 형식 호환성은 실제 호출로 확인해야 합니다.
서로 다른 식별자를 등록하는 것만으로 모델의 기술적 독립성이나
평가의 정확성이 입증되는 것은 아닙니다.


5. 선택 환경변수와 기본값
------------------------
DAILY_AI_LIMIT=50
  서버 프로세스 전체의 하루 피드백 요청 수 상한입니다.
  외부 AI 호출 수 자체의 상한은 아닙니다.

VOTE_MARGIN=0.20
  통합 판단의 1순위와 2순위 점수 차이 기준입니다.

VOTE_MIN_SCORE=0.65
  통합 판단의 최상위 점수 기준입니다.

VOTE_MAX_SPREAD=0.30
  같은 클래스에 대한 모델 간 최대 점수 편차 기준입니다.

판단 임계값은 0~1 범위여야 합니다.
기본값은 교육용 초기 설정이며, 실제 성능 검증으로 최적화한 값이 아닙니다.


6. 다중 모델 검토 방식
---------------------
각 모델은 동일한 분석 근거와 학생 답안을 받아 q1~q3을 각각 평가합니다.
다른 모델의 응답은 전달받지 않습니다.

문항별 판단 클래스
- supported: 근거에 대체로 부합
- revise: 수정 필요
- unsupported: 핵심 주장에 근거가 부족하거나 오류가 있음

모델은 클래스별 0~1 판단 점수와 설명을 반환합니다.
출력 형식, 점수 범위, 합계를 검증하며 합계는 1에서 0.02 이내의 차이만
허용한 뒤 정규화합니다. 형식·범위·합계 오류는 해당 모델의 실패로 처리합니다.

통합 점수
  S(c) = sum(weight_i × score_i(c)) / sum(weight_i)

초기 가중치는 모두 1을 권장합니다. 모델 우열을 확인한 검증 자료가 없으므로
특정 모델에 더 큰 가중치를 줄 근거가 확보되어 있지 않습니다.

다음 조건을 모두 충족해야 문항을 'AI 잠정 채택'으로 표시합니다.
- 설정된 모든 모델이 성공하고 유효 응답이 2개 이상
- 모든 모델의 1순위 판단이 일치
- 통합 최상위 점수가 VOTE_MIN_SCORE 이상
- 통합 1·2순위 점수 차이가 VOTE_MARGIN 이상
- 클래스별 모델 간 최대 점수 편차가 VOTE_MAX_SPREAD 이하

하나라도 충족하지 못하면 사람 검토 필요(HITL)로 표시합니다.
일부 모델 실패 시 남은 점수는 참고로 표시하지만 자동 채택하지 않습니다.
전체 모델 실패 시 표시되는 0점은 실제 평가 점수가 아니라 유효 응답이
없다는 결과입니다. 모델 오류 안내를 확인하세요.

점수는 통계적으로 보정된 확률, 실제 정답 확률 또는 정확도가 아닙니다.
여러 모델이 같은 오류에 합의할 수도 있습니다.
'AI 잠정 채택'도 교사가 수정할 수 있으며 공식 성적이 아닙니다.

현재 화면의 30점·30점·40점 안내는 기존 단일 모델 평가 설명입니다.
현재 다중 모델 경로는 해당 100점 총점을 산출하지 않습니다.

가중치와 임계값을 조정하려면 교사가 라벨링한 검증 자료를 사용하고,
조정에 사용하지 않은 별도 테스트 자료로 성능을 확인해야 합니다.


7. 학생·심사위원 사용 순서
-------------------------
1) 배포된 HTTPS 주소에 접속하고 입장 코드를 입력합니다.
2) 가상 데이터로 시작하거나 개인정보가 없는 CSV를 불러옵니다.
3) 상관분석, 회귀 학습·평가, 새 값 예측, 신뢰구간 계산을 완료합니다.
4) 실무 미션의 세 답안을 작성합니다.
5) 'AI에 보낼 분석 근거 확인'으로 전송 내용을 점검합니다.
6) 개인정보가 없음을 확인하고 외부 AI 전송에 동의합니다.
7) 다중 모델 검증·피드백을 요청합니다.
8) 모델별 설명과 통합 판단을 확인합니다.
9) '06 사람 검토(HITL)' 탭에서 문항·최종 판단·수정 이유·검토자 별칭을
   기록하고 검토 기록을 별도로 저장합니다.
10) 실습 결과 저장 버튼으로 분석·답안·유효한 피드백을 저장합니다.

데이터와 답안은 새로고침하면 사라지므로 필요한 결과를 먼저 저장하세요.
답안이나 분석을 변경했다면 AI 평가를 다시 요청하고 사람 검토 기록도
새로 작성하세요. 이전 판단을 그대로 재사용하지 마세요.


8. 요청 제한과 비용 주의
-----------------------
현재 구현의 제한
- 세션당 하루 피드백 요청 한도: 10회
- 서버 프로세스 전체 하루 피드백 요청 한도: 기본 50회
- 동시 피드백 처리: 최대 3개
- 각 피드백 요청은 설정된 모델 수에 따라 외부 AI를 최대 3회 호출
- 모델 요청 실패 시 자동 재시도하지 않음
- 세션·전체 한도에 반영된 뒤 발생한 모델 실패도 요청 횟수에 포함
- 요청이 거절된 시점에 따라 일부 제한 카운터만 증가할 수 있음
- 날짜 기준: UTC

횟수와 동시 처리 제한은 프로세스 메모리에 저장됩니다.
서버 재시작 시 초기화되며 여러 워커·인스턴스 간에는 공유되지 않습니다.
쿠키 삭제나 재입장으로 새 세션이 만들어지면 세션 한도도 새로 적용됩니다.
따라서 재시작·확장에 무관한 엄격한 사용자별 제한이나 예산 통제가 아닙니다.

외부 AI 서비스 자체의 사용량 제한과 예산도 반드시 설정하세요.
장기 운영에는 DB/Redis 기반 제한과 적절한 계정 인증 등을 추가해야 합니다.
입장 코드는 보조 통제이며 사용자별 인증을 대신하지 않습니다.


9. 개인정보와 데이터 처리
-------------------------
통계·모델 계산은 브라우저에서 수행합니다.
프런트엔드의 AI 요청에는 원본 CSV 행을 직접 포함하지 않고,
데이터 요약, 변수별 요약통계, 분석 근거, 학생 답안을 전송합니다.

그러나 변수명·범주 라벨·극값·자유 답안에도 개인을 식별하거나
민감한 내용을 드러내는 정보가 포함될 수 있습니다.
원본 행을 보내지 않는다고 완전히 익명화되는 것은 아닙니다.

- 가상 데이터 또는 적절히 비식별화한 자료임.
- 이름·학번·연락처·민감정보를 변수명이나 답안에 입력하지 마세요.
- API 키는 서버에서만 사용하고 HTML·결과물·공개 저장소에 넣지 마세요.
- 앱은 데이터와 답안을 DB에 저장하도록 구현되어 있지 않습니다.
- 결과·검토 기록은 사용자가 직접 파일로 내려받습니다.
- 호스팅 로그와 외부 AI 서비스의 보관·처리 정책은 별도로 확인해야 합니다.
- 실제 학생 대상 장기 운영 전에는 동의 절차와 개인정보 처리 안내를
  기관 정책에 맞게 보완하세요.


10. 사람 검토의 구현 범위
------------------------
사람 검토는 화면의 자유 입력과 텍스트 파일 저장 기능입니다.
서버 측 검토 대기열, 검토자 계정 인증, 승인 이력 DB는 없습니다.
따라서 인증된 교사의 공식 승인 기록 시스템으로 설명하면 안 됩니다.

검토 기록에는 문항, 최종 판단, 수정 이유, 검토자 별칭을 남기세요.
개인정보는 입력하지 마세요.


11. 분석과 평가의 한계
---------------------
- 가상 자료의 결과는 실제 학생 성과나 프로그램의 교육 효과를 입증하지 않습니다.
- 상관관계는 인과관계를 입증하지 않습니다.
- 브라우저가 보내는 계산 결과를 서버가 원본 CSV로 재검산하지 않습니다.
- AI는 제공된 근거와 답안을 비교하며 원본 자료를 재분석한 것이 아닙니다.
- 고정 시드 80/20 분할 1회의 결과이며 교차검증·확률 보정은 미실시입니다.
- 모델·표본·분포·대표성의 한계를 검토해야 합니다.
- 공식 시험 성적, 학생 선발·평가, 부정행위 검증 도구로 사용하지 마세요.
- 실제 학습 효과는 별도의 사전·사후 평가와 사용자 검증으로 확인해야 합니다.

현재 프런트엔드에서 추가 확인·개선이 필요한 사항
- 기본 회귀와 고급 모델이 공유하는 기록에 서로 다른 모델 근거가 섞일 가능성
- 고급 예측 입력 변경 시 기존 예측·피드백을 무효화하는 처리
- 데이터·설정 변경 후 남는 이전 예측·그래프·사람 검토 기록의 상태 표시

이 안내서를 통합한 것만으로 위 코드 문제가 수정된 것은 아닙니다.
