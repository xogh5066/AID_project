다중 모델 CSV 실습 검증 버전

기존 README의 호스팅 배포 방식과 입장 코드, SESSION_SECRET 설정을 사용합니다.
AI_API_URL/KEY/MODEL 단일 설정 대신 다음을 등록하세요.
ENSEMBLE_MODELS_JSON: models.example.json 내용을 실제 값으로 변경한 JSON 배열
MODEL_A_KEY, MODEL_B_KEY: 실제 비밀 API 키. 필요하면 MODEL_C_KEY 추가
각 항목 url=전체 Chat Completions 호환 주소, model=정확한 식별자,
key_env=실제 키를 저장한 환경변수 이름, weight=양수 가중치.
동일 Gateway에서 서로 다른 모델을 쓰면 동일 주소/동일 키 환경변수 이름을 써도 됩니다.
서로 다른 모델 식별자 2~3개가 필수입니다. 모델 이용 권한과 호환성은 직접 확인해야 합니다.
키를 HTML, GitHub, 모델 예시 파일에 적지 마세요.

추가 선택 환경변수
VOTE_MARGIN=0.20 / VOTE_MIN_SCORE=0.65 / VOTE_MAX_SPREAD=0.30
DAILY_AI_LIMIT=50 : 피드백 요청 횟수이며 외부 AI 호출은 요청당 최대 3회입니다.
각 호출은 별도 과금될 수 있습니다. 실패 시 자동 재시도하지 않습니다.
기존 gunicorn 1 worker/4 threads/120초 설정 유지. 단일 인스턴스 시연용입니다.

구현 범위
CSV 회귀는 기존 통계 계산을 사용하며 여러 LLM의 숫자 예측을 평균내지 않습니다.
각 LLM이 q1~q3 답안의 해석 타당성을 세 클래스 점수로 독립 평가합니다.
점수는 비보정 판단 점수입니다. 실제 정답 확률이나 확률적 신뢰도로 주장할 수 없습니다.
초기 가중치는 모두 1. 실측 검증셋이 없으므로 모델 우열을 임의로 가정하지 않았습니다.
가중치/임계값은 교사 라벨 검증셋으로 조정하고 별도 테스트셋으로 성능 확인 후 사용하세요.
문항별 S(c)=sum(weight_i * score_i(c))/sum(weight_i).
전 모델 성공, 1순위 일치, 최상위 점수/점수 차이/최대 클래스별 모델간 편차 기준을
모두 만족해야 AI 잠정 채택. 하나라도 불충족하면 HITL. 부분 실패 시 남은 모델 점수는
참고 표시만 하며 자동 채택 금지. 출력 형식/범위/합계 오류도 실패 처리합니다.
결과의 합의는 정답을 보장하지 않습니다. 공식 자동 채점에 사용하지 마세요.
브라우저가 보내는 근거를 원본 CSV로 서버에서 재검산하지 않는 시연 구조입니다.
